# gesture-engine — Subsystem Context

## What This Library Does

`gesture-engine` is a C++17 static library that turns per-frame 21-joint hand
tracking input into discrete gesture events for the compositor and shell to act
on.

**Inputs:** `ge_hand_t hands[2]` — joint positions + tracking confidence, per hand,
per frame (typically 60 Hz from the wxrd hand-tracking pipeline).

**Outputs:** `ge_event_t` callbacks emitting `Begin` / `Update` / `End` / `Cancel`
events with payload data appropriate to the gesture (e.g. 3-D drag delta for
`grab_window`, scalar projection for `scroll`, rotation around vertical for
`fist_launcher`).

Each gesture is a small priority-tagged state machine
(Idle → Pending → Active → End/Cancel) driven by feature extraction over the
joint cloud.

## Building & Testing

```bash
cmake -G Ninja -S gesture-engine -B build/gesture-engine
ninja -C build/gesture-engine
cd build/gesture-engine && ctest --output-on-failure
```

Tests use synthetic hand poses and need no hardware.

The `replay_hands` tool reads a captured SPHD-format joint log and feeds it
through the engine — useful to reproduce a finnicky moment from a wxrd-side
recording.

For iPhone-recorded clips (live wire-protocol `0x05` hand packets in
`stream.bin`), use the **`eval_recording`** tool instead — it parses the
length-framed UDP-format bin directly and emits one `EVT` line per gesture
event:

```bash
build/gesture-engine/tools/eval_recording \
    ~/spatial-os-recordings/<id>/stream.bin --gestures-only
build/gesture-engine/tools/eval_recording \
    ~/spatial-os-recordings/<id>/stream.bin --features      # joint-feature dump
```

### Dataset eval

The **`eval_dataset_smoke` ctest entries** wrap `scripts/eval_dataset.py`,
which runs detection against every clip in `~/spatial-os-recordings` and
compares each `BEGIN` against the per-clip `labels.json` keyframes under the
±300 ms tolerance.  They SKIP (NOT_RUN) when the recordings directory is empty
or absent, so they never break CI on a fresh checkout.  An unkeyed clip is
reported as SKIP and is not counted as a pass.

Invalid recording input is a failure even when there are no keyframes:
missing labels or metadata, an empty/no-hand stream, or truncated packet framing must
not turn into a successful unscored run. `test_eval_input` exercises these
paths through the real replay binary and Python evaluator. A missing mirror
still skips; a valid unkeyed clip still runs and remains unscored.

```bash
ctest --test-dir build/gesture-engine -R eval_dataset --output-on-failure
python3 scripts/eval_dataset.py --eval-recording build/gesture-engine/tools/eval_recording
```

**On this machine these are smoke / regression checks only — not accuracy
gates.**  `~/spatial-os-recordings` holds 8 clips generated by
`scripts/gen_synthetic_session.py` (synthetic joints and synthetic keyframes,
2026-08-29 ids); the ctest names carry `_smoke` for that reason.  A pass
proves the `eval_recording` binary runs end-to-end on every clip and the
harness judges its output; it says nothing about real-hand detection.  Never
tune a threshold, filter, or gate to make a synthetic clip pass, and never
generate more synthetic clips as "data".

The **35/56 baseline** quoted below was measured on 56 real iPhone
recordings (2026-05/06 ids listed in `tests/datasets/dataset_split.json`)
that are **not present here** — it cannot be reproduced on this checkout.
Treat it as history until those recordings are restored; an accuracy number
needs real labelled clips.

The dataset is **split 80/20** deterministically (SHA-1 of clip id mod 5,
bucket 0 → TEST, buckets 1–4 → TRAIN; see
`gesture-engine/tests/datasets/dataset_split.json`).  Three ctest entries:

- `eval_dataset_train_smoke` — with real clips, the set you tune against.
- `eval_dataset_test_smoke`  — with real clips, held out.  Measure only; do
  not drive tuning decisions from it.  If TEST drops more than ~5% relative
  to TRAIN after a change, that's overfit — stop and escalate.
- `eval_dataset_smoke`        — both buckets together, for the "do not
  regress" global number.

The Python harness takes `--split {train,test,all}` to match.

Historical baseline (2026-07-04, real recordings, ±300 ms tolerance — the
user set this window so the suite scores *detection* rather than BEGIN-timing
slop): **ALL 35/56.**  (Same engine scored only 10/56 at ±50 ms — that
~45-point gap is BEGIN-timing slop, not detection failure.)

> The ±50 ms window was the original hard spec but it swamped the "did the right

> default back to ±300 ms (`DEFAULT_TOL_{EARLY,LATE}_MS` in
> `scripts/eval_dataset.py`).  Tightening BEGIN-to-keyframe timing is still

> the window — but do not silently narrow it, and if it's ever too tight for
> hold-gestures, add an honest per-gesture hold offset rather than re-widening.

Historical (measured at the old ±300 ms window, 2026-06-09): TRAIN 28/39, TEST
4/8, ALL 32/47.  Notable eval-harness/engine changes from that era: match

**Why `grab_window` is still out (checked 2026-09-04, do not re-enable
blind).** Unlike the other two it *does* have a consumer — mac-shell's
`scene::on_gesture` handles `GE_ACTION_WINDOW_MOVE` end to end (grab deadband,
re-anchor on drop) and the gesture cheat sheet advertises "grab + move".  The
blocker is the thresholds, and they are inverted rather than merely loose: on
every clip in the recording mirror an **idle open hand** reads ti 0.051 /
thumb↔middle 0.062 / thumb↔ring 0.067 / thumb↔pinky 0.070, which satisfies all
four trigger conditions continuously from frame 0, while during an actual
pinch the middle finger moves *away* (thumb↔middle 0.072–0.077) and the
trigger stops matching.  Compiling the block in fires `WINDOW_MOVE` BEGIN at
167 ms on a resting hand and never releases (release wants ti > 0.085), which
starves `pinch_select` and turns three eval suites red; dropping its priority
below `pinch_select` fixes the starvation but not the false grabs.  This
subsystem doc records real users resting at ti 12–18 mm — deeper inside the
band than the synthetic fixture — so it is not a fixture artifact, and it is
the same failure the user reported on 2026-05-19 ("every time I try to click,
I end up dragging it").  New distances plus a convergence gate are needed:
that is `grab-threshold-tune` in `/BACKLOG.md`, a **Track B in-person** task.
`tests/test_gestures.cpp::test_grab_window_stays_uncompiled` pins this so the
next reader has to read the reason first.  Until it lands, the cheat sheet's
"grab + move" row has no emitter.

verified: 2026-09-04 -- gesture-engine/src/engine.cpp mac-shell/src/core/scene.cpp

**Hysteresis margins (2026-09-02):** every pinch variant releases 13 mm past
its trigger — the margin the standard variant documents (35 → 48 mm: 10 mm
plus residual post-filter jitter).  `loose` / `double_tap` / `palm_up`
previously released *below* their trigger (38 / 40 / 60 mm), so they ended
on the frame after BEGIN — which also masked that `loose` fires in its 38–75
mm band whenever the thumb approaches with > 0.08 m/s closing velocity.  Now
that it genuinely fires there, its velocity gate sits at the noise floor
(±3.5 mm per 30 Hz frame ≈ 0.1 m/s), so `window_max_closing_velocity_mps`
reports 0 while the window is net-opening and every pinch variant carries
the 250 ms click cap.  Whether 0.08 m/s is the right gate for real hands is
a **Track B judgment call** — tune in person, not against synthetic clips.
`keyboard_anchor`'s curl release moved 0.15 → 0.25 for the same reason
(0.15 was below its 0.18 trigger).  `tests/test_gestures.cpp::
test_release_wider_than_trigger_for_every_variant` enforces the invariant
over every compiled pair.

**Convergence gate (2026-09-02):** `pinch_select.standard` requires
`thumb_index_convergence_ratio` ((max − min) / max of ti over 500 ms) > 0.10,
down from 0.20, so a hand resting at 12–18 mm closes ~1.5 mm instead of 3 mm
to click ("minimize hand motion").  0.10 is the gate `pinch_right_click`
already used; the `#if 0` shape-based variant was not re-enabled because it
gates on ratio > 0.40 — *more* rest-dependent, not less.

**Important gesture-design rules** (per memory: don't regress these):

- **Right-click is thumb↔middle pinch with a direction check**
  (`middle_tip_direction_to_thumb_cos > 0` plus the ti convergence ratio),
  not raw distance.  Without it you get false right-clicks when the user's
  hand is relaxed and the thumb brushes near the middle finger.  It outranks
  `pinch_select` (priority 3 vs 1): a pinch_select that fired first on the
  3-finger pose is CANCELled when the right-click promotes — consumers act on
  click END, never BEGIN alone.
- **Close is fingertip-gather**, not a thumb-middle pinch — when it comes
  back.  It is not compiled today, and nothing routes `GE_ACTION_WINDOW_CLOSE`
  to it.  Note the cheat sheet's "double-pinch the air → gather your windows"
  is a *different* interaction and is already served: mac-shell counts two
  empty-space `POINTER_CLICK` BEGINs inside `DOUBLE_PINCH_GATHER_S` and calls
  `gather_panels_impl()`.  Re-enabling `fingertip_gather_close` would add a
  window-CLOSE gesture, not a gather — don't conflate them.
- Use projection math (point onto polyline) where possible; raw Euclidean distance
  is too noisy at this hand-tracking precision.

## Config Schema (`~/.config/spatial-os/gestures.toml`)

A user can override any threshold or hold-time without recompiling.  The
file is plain TOML; the engine merges it on top of the compiled defaults
in `src/engine.cpp::add_default_gestures()`.  Per-line errors are logged
to stderr but do not abort loading — partial overrides still apply.

**Sample:** `gesture-engine/sample-config/gestures.toml` is the canonical
exhaustive sample, mechanically generated by
`tools/print_default_config`.  `test_config.cpp::
test_sample_config_roundtrip_is_noop` (ctest `test_gestures_config`) fails
when the file drifts from the compiled defaults, and also asserts that
loading it changes nothing (`ge_print_config` after load == default dump).

**Regenerate after changing defaults:**

```bash
cmake --build build/gesture-engine
build/gesture-engine/tools/print_default_config > gesture-engine/sample-config/gestures.toml
```

**Schema:**

```
[filter]                                   # global — joint filtering, not a gesture
one_euro_enabled               = <0|1>
one_euro_min_cutoff_hz         = <float>   # > 0
one_euro_beta                  = <float>   # >= 0
one_euro_d_cutoff_hz           = <float>   # > 0
min_joint_confidence           = <float>   # 0..1

[<gesture_name>]                           # applies to EVERY variant of the name
[<gesture_name>.<variant>]                 # applies to one variant
min_hold_ms                    = <int>     # how long trigger must hold before BEGIN
cooldown_ms                    = <int>     # min gap after END/CANCEL before re-trigger
max_active_ms                  = <int>     # auto-END after this long Active (0 = never)
indeterminate_release_ms       = <int>     # give up after this long of NaN features
trigger.<feature_name>         = <float>   # threshold for an existing trigger condition
release.<feature_name>         = <float>   # threshold for an existing release condition
trigger.<feature_name>.<op>    = <float>   # selects one of two conditions on the same feature
```

| Key                        | Type   | Notes |
|---|---|---|
| `[<gesture_name>]`         | section | One of: `keyboard_anchor`, `fist_launcher`, `pinch_right_click`, `scroll`, `pinch_select`.  Applies every key to **all** variants of that name. |
| `[<gesture_name>.<variant>]` | section | One variant: `fist_launcher.{per_frame,windowed}`, `scroll.{tight,wide}`, `pinch_select.{standard,loose,double_tap,palm_up}`.  Sections apply in file order, so a bare section followed by a variant section refines it.  A **repeated header** (same text twice) is logged and the repeat's keys are ignored — the old sample printed four bare `[pinch_select]` blocks and the last one silently rewrote the first variant. |
| `min_hold_ms`              | int    | Minimum time the trigger must continuously match before the gesture fires `BEGIN`. |
| `cooldown_ms`              | int    | After END/CANCEL, the gesture cannot re-enter Pending for this long. |
| `max_active_ms`            | int    | Auto-END after this long in Active even if release conditions aren't met (click-type gestures). 0 disables.  Defaults: 250 on every `pinch_select` variant and `pinch_right_click`, 10 000 on `fist_launcher` (a hold-and-scrub whose END commits the focused wedge in mac-shell — a click-length cap would commit for the user), 0 elsewhere. |
| `indeterminate_release_ms` | int    | Budget for NaN features (zero-frame artifact or sub-`min_joint_confidence` joint).  Active + release unreadable this long → **CANCEL**; Pending + trigger unreadable this long → hold resets; disarmed name + trigger unreadable this long → counts as released for rearm.  Default 300. |
| `trigger.<feature>`        | float  | Replaces the threshold of every trigger condition keyed by `<feature>`.  The comparison operator (`less` / `greater` / `less_eq` / `greater_eq`) is **not** overridable — it's part of the compiled definition. |
| `trigger.<feature>.<op>`   | float  | Same, restricted to the condition with that comparison.  Needed where one feature carries two conditions (`scroll.wide`'s 20 mm < ti < 70 mm band); the sample prints the suffix only there. |
| `release.<feature>`        | float  | Same, for a release condition.  Release uses *any-of* semantics (any release condition matching ends the gesture); trigger uses *all-of*. |
| `[filter]` section         | —      | Global jitter-filter tuning, see below.  `min_cutoff` / `d_cutoff` ≤ 0, `beta` < 0, or a confidence outside 0..1 is logged and the compiled default kept. |

**Tuning — jitter robustness (2026-08-29):**

- **One-Euro joint filter** (`src/one_euro.h`, applied in `ge_update` per
  engine hand before feature extraction).  `one_euro_min_cutoff_hz` (default
  1.5) sets jitter rejection at rest — lower = smoother but laggier;
  `one_euro_beta` (default 30, per m/s) opens the cutoff with speed so
  intentional motion stays snappy (a 1 m/s pinch approach runs the cutoff to
  ~30 Hz ≈ no lag); `one_euro_d_cutoff_hz` (default 1.0) smooths the speed
  estimate so alternating-sign noise can't fake "fast motion".  Zero-frame
  artifacts and sub-`min_joint_confidence` joints bypass the filter (raw +
  filter reset) so garbage never pollutes its history.
- **`min_joint_confidence`** (default 0.15): fingertips below it are treated
  exactly like zero-frame artifacts — derived features go indeterminate
  (NaN), so low-confidence joints cannot drive triggers.
- **Rearm-on-release debounce** (not configurable; `engine.cpp`
  `kRearmReleaseMs` = 100): after a gesture name emits END/CANCEL on a hand,
  no variant of that name can re-enter Pending until its trigger has been
  continuously un-met for 100 ms.  This is what makes a continuously-held
  pinch emit exactly one BEGIN/END pair — cooldown alone re-fires because
  the trigger is still met when the cooldown expires.  Real double-taps
  release ≥ 130 ms between beats, so they still work.  An *indeterminate*
  trigger (NaN) counts as held only for `indeterminate_release_ms`; past
  that it counts as released, so an occluded joint can't disarm a name
  forever.
- **Indeterminate budget** (`indeterminate_release_ms`, default 300, per
  gesture, TOML-overridable): NaN comparisons are false, so before 2026-09-02
  an Active gesture whose release feature went NaN never released.  Now
  Active + unreadable release → CANCEL after the budget; Pending freeze and
  rearm are capped by the same number (`test_indeterminate_*` in
  `tests/test_gestures.cpp`).
- **Velocity gating**: `wrist_speed_mps` (EMA over ~100 ms of the filtered
  wrist) is a feature; pinch/scroll/right-click variants carry
  `trigger.wrist_speed_mps < 0.8` so a pose materialising mid-fast-sweep
  (usually tracking noise) can't fire.  TOML-overridable per gesture like
  any trigger threshold.
- **Noisy fixtures**: `tests/test_gestures.cpp` (`test_noisy_pinch_hold_…`,
  `test_fast_wave_…`, `test_near_threshold_oscillation_…`) lock this
  behaviour in; `scripts/gen_synthetic_session.py --noise rigid=MM,joint=MM`
  generates noisy clips (per-joint noise is amplified by `hr_reconstruct` —
  use rigid-dominant noise to model ±10 mm engine-boundary jitter).
- Introspection: `ge_filter_param()`, `ge_gesture_cooldown_ms()`,
  `ge_gesture_max_active_ms()`, `ge_gesture_indeterminate_release_ms()`
  alongside the existing accessors; `ge_gesture_count()` /
  `ge_gesture_name_at()` / `ge_gesture_variant_at()` /
  `ge_gesture_condition_count()` / `ge_gesture_condition_at()` enumerate the
  compiled definitions (used by the hysteresis-invariant test and by
  `calibrate.cpp` to emit only compiled gesture sections).

Unknown gesture names, unknown field names, missing files, and unparseable
values are all logged to stderr and skipped.  No combination of bad input
will leave the engine in a broken state — at worst it silently runs with
compiled defaults.

**Programmatic introspection** (for tools / tests):

```c
int   ge_gesture_min_hold_ms(const ge_engine_t *ge, const char *gesture_name);
float ge_gesture_threshold (const ge_engine_t *ge, const char *gesture_name,
```

**Default config path:** `$XDG_CONFIG_HOME/spatial-os/gestures.toml`,

`ge_load_config()` to use this default; pass an explicit path to override
(used by tests and by `--gestures-config` on `replay_hands`).

## Architecture Notes

### Priority-suppression model

Gestures are sorted descending by priority at engine creation. Each frame, the
driver iterates the list in order. When a gesture becomes `Active`, it claims its
hand for that frame and prevents lower-priority gestures from entering `Pending`
on the same hand. This is why `pinch_right_click` (priority 3) beats
`pinch_select` (priority 1) when both could match — the user clearly meant the
more specific one.  Same-name variants never pre-empt each other: once one
variant is Active on a hand, the others cannot promote until it ends.

### Hysteresis

Every gesture has separate trigger and release thresholds (e.g.
`pinch_select.standard` triggers at 0.035 m, releases at 0.048 m). Without
this, tracking jitter causes rapid Begin/End flapping at the boundary.  The
release must sit strictly on the far side of the trigger for every pair on
the same feature — `test_release_wider_than_trigger_for_every_variant`
enforces it.

### Feature extraction (`ge_features.{h,cpp}`)

Per-frame, the engine computes:

- Finger-tip pair distances (thumb↔index, thumb↔middle, …).
- Finger curl values 0..1 (0 = straight, 1 = fully closed) from joint angles.
- Thumb projection onto the index-finger polyline (MCP→PIP→DIP→TIP) — both the
  perpendicular distance and the scalar projection.
- Fingertip gather radius around the centroid of all five tips.
- Palm normal (cross product of palm-vector bases) and palm centre.
- Pinch midpoint (3-D centre of thumb-tip + index-tip).

These features are what gesture predicates check. If you need a new gesture,
prefer adding to this feature set over re-deriving from raw joints inside each
gesture predicate.

### Handedness — `ge_hand_chirality`, never a slot index

`ge_hand_chirality(const ge_hand_t *)` → `GE_CHIRALITY_LEFT` / `RIGHT` /
`UNKNOWN`, plus the bool wrapper `ge_hand_is_left(const ge_hand_t *)`.  Both
are stateless and live in the public header.

**Never derive handedness from a slot.**  `ge_update`'s `hands[0]` / `hands[1]`
and `ge_event_t::hand_index` are *identities*, not chirality — the header says
so, and the iPhone's `hand_index` is a sticky first-seen slot, so a right hand
that lands in slot 0 once stays there for the whole session.  Anything whose
SIGN depends on handedness silently inverts for the rest of the session when it
reads `slot == 0`; the live example is the launcher's fist-roll scrub, whose
mirror lands in `vendor/wxrd/src/fist_rotation.c::angle_from_dir(dir, is_left,
…)` via `launcher_menu::update_rotation`.

The test is the signed volume of the tetrahedron wrist / INDEX_MCP / PINKY_MCP
/ thumb, normalised by `compute_hand_scale` so the decision is size-free
(`ge::palm_thumb_signed_offset` in `ge_features.cpp`).  The palm-plane normal
`(INDEX_MCP−WRIST) × (PINKY_MCP−WRIST)` points **palmar on a right hand** and
dorsal on a left one in the right-handed ARKit frame — the same convention that
makes `palm_normal` read palm-facing and `keyboard_anchor` gate on
`palm_normal_y < −0.85` for palm-down — and the thumb is opposable, so it is
anatomically always on the palmar side.  Positive ⇒ right, negative ⇒ left.
The thumb reference averages MCP/IP/TIP (the CMC sits in the palm plane and
only dilutes).

`UNKNOWN` below 0.2 proximal-phalanx lengths of offset is a **degeneracy
guard, not a tuned threshold**: a perfectly flat hand is its own mirror image
and genuinely has no chirality, so returning "cannot tell" beats a coin flip
that would invert a scrub mid-session.  A caller driving a continuous signal
should latch the last decided value.

**Unverified against real hands.** The sign convention is derived from the
joint layout and cross-checked against the two conventions above; the tests use
mirrored synthetic fixtures.  It is *not* validated on recorded clips: the
mirror's `gen_synthetic_session.py` hand model is deliberately near-planar
(thumb ≈ 0.02–0.08 of the palm normal, to keep motion ray-perpendicular for
`hr_reconstruct`), so it reads UNKNOWN and carries no chirality to check
against.  Confirm on a real hand before trusting the scrub direction.

### Confidence filtering

Confidence is handled at two levels — but **not** by dropping individual joints
before feature computation:

1. **Hand-level gate (upstream, in wxrd).** `hand_input.c` computes the mean
   confidence over all 21 joints and marks the whole hand `present = false` when
   it falls below `MIN_JOINT_CONFIDENCE` (0.15). If the hand clears the gate, all
   21 joints are copied verbatim into the `ge_hand_t` — including individually
   low-confidence ones. There is no per-joint drop here.
2. **Confidence-as-feature (in the engine).** `ge_features.cpp` computes every
   distance/curl feature from all 21 joints unconditionally, and *also* exposes
   confidence as its own features (`min_confidence`, `*_tip_confidence`,
   `middle_tip_confidence_min_over_200ms`). Individual gesture predicates may gate
   on these (e.g. `middle_tip_confidence < 0.55`), but that is opt-in per gesture,
   not a global pre-filter.
3. **Indeterminate fingertips (2026-08-29).** Fingertips below the
   `[filter] min_joint_confidence` gate (default 0.15) get the same treatment
   as zero-frame artifacts: features derived from them read NaN, triggers
   reading NaN don't fire, and a Pending hold freezes rather than resets —
   for at most `indeterminate_release_ms` (300 ms); past that the hold
   resets and an Active gesture CANCELs.

Note the engine does **not** zero low-confidence joints either — zeroing would
collapse a joint to the origin and produce large false distances (see the
"(0,0,0) garbage" hazard around `engine.cpp:745`). A noisy low-confidence
fingertip below the gate goes indeterminate (NaN) instead — never a fallback
value, so a gesture simply cannot fire off an unreliable joint.

## "What good looks like" for this subsystem

- User can edit `~/.config/spatial-os/gestures.toml` and the engine picks up the
  new thresholds on next launch — no recompile.
- A 30-second calibration brings false-trigger rate to under 1 event per
  10-minute idle session for an average user.
- New gestures take less than an hour to add: define a `GestureDef` in
  `engine.cpp`, declare its predicate against the existing feature set, give it a
  priority, add a synthetic-hand test.
- Replay tool reproduces any reported gesture bug from a recorded session.

## Gotchas

- **Don't add fallbacks for low-confidence joints.** If the joint is unreliable,
  the gesture should not fire — silently ignoring missing data is how
  false-positives sneak in.
- **Don't tighten thresholds to fix flapping.** Use or extend hysteresis (separate
  trigger/release values) instead. Tightening is what got us into the current
  finnicky state.
- **Priority order matters.** Adding a new low-priority gesture that overlaps
  with a high-priority one is fine; the reverse causes the existing high-priority
  gesture to disappear. Always check the suppression matrix in your head before
  changing a priority.
- **Holds are minimums, not exact.** `min_hold_ms` means "must be matching for at
  least this long before transitioning to Active". The user's actual hold can be
  longer; only `max_active_ms` (click gestures) and `indeterminate_release_ms`
  (unreadable features) end a gesture on their own.
- **Synthetic clips are plumbing checks.** The `eval_dataset_*_smoke` entries
  and `scripts/gen_synthetic_session.py` output exercise the harness; they are
  not ground truth.  Do not pick a threshold, filter, or gate value because a
  synthetic clip passed with it.  (They still catch gross plumbing breakage —
  an idle hand that fires a gesture shows up here first.)
- **A hand slot is not a handedness.** `hands[0]` / `event->hand_index` are
  identities the engine remaps by position continuity; `slot == 0` is not
  "left".  Call `ge_hand_chirality` — see "Handedness" above.
